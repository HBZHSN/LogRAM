# 桌面界面规范

独立 GUI 使用 WPF，Notepad++ 查看器使用 WinForms。两个工作区均按上方日志原文、下方搜索结果组织，以键盘导航、分页和只读复制为核心。 [界面组件](COMPONENTS.md) · [使用截图](../README.md)

| 项目 | 现有约定 |
| --- | --- |
| 颜色和字体 | WPF 沿用主窗口深浅主题和用户字体设置，日志默认 Consolas 12。插件随 NPP 深浅主题，图标跟随主题前景色。 |
| 布局 | WPF 主窗口最小尺寸为 820 × 520，原文和结果区可拖动调整。NPP 查看器适应宿主编辑区，工具栏位于结果区顶部。 |
| 交互状态 | 加载和搜索提供进度与可用操作，选项切换可见，错误说明原因或恢复方式。长日志按可见页渲染，避免将整份正文放入控件。 |
| 键盘与无障碍 | 保留搜索、行号跳转、上一条和下一条的快捷键。图标按钮通过 Tooltip 和无障碍名称表达用途。NPP 继续使用宿主的文件及标签快捷键。 |
| 语言 | 桌面标签和提示使用中英文资源。独立 GUI 由用户选择，插件使用 NPP 的语言设置。 |

主题、尺寸和无障碍名称的实现以各入口源码为准。涉及布局时核对深浅主题、最小窗口和文本长度变化，宿主交互以便携版 NPP 回归为据。 [WPF 主窗口](../LogRAM/MainWindow.xaml) · [GUI 设置](../LogRAM/AppSettings.cs) · [NPP 查看器](../LogRAM.Npp.Viewer/ViewerForm.cs) · [界面验证](TEST_STYLE.md#界面与真实环境)

## UI 文案与信息密度规范

### 核心原则

界面供用户操作。每段可见文字须提供新信息、帮助决策或指导必要操作。

### 禁止行为

- 为已能表达用途的标题、按钮、开关、表格或卡片添加重复说明。
- 添加无业务价值的欢迎语、宣传语、功能介绍区或工具页顶部的大幅横幅。
- 用描述、卡片、图标和标题填充版面，或套用固定的标题、副标题、说明与按钮编排。
- 照搬需求原文作为界面文案，或使用“轻松管理”“高效便捷”“一站式”“开启全新体验”等空泛用语。

### 默认设计行为

- 真实数据、操作入口与当前状态优先，标题命名当前位置。
- 按钮使用具体动作词，例如“刷新”“导出”。让控件和数据承担能直接表达的信息。
- 保持操作区紧凑。次要帮助使用 Tooltip、帮助入口或按需展开。
- 延续现有组件、布局、术语和中英文文案。

### 必须保留的说明

- 不可逆操作的风险和确认。
- 用户无法从控件推知的规则、单位与参数含义。
- 输入限制、校验错误、修复方式和必要的空状态引导。
- 无障碍名称和能帮助完成任务的提示。

### 完成前审查

逐项检查文字是否帮助用户理解、决策或操作，是否重复相邻内容，是否能由控件或真实数据直接表达。仅保留支撑任务的文案，将设计约定留在维护文档。
